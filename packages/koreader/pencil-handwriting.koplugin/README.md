# Pencil handwriting

KOReader 手写批注插件：在墨水屏阅读器上直接用数字笔在页面上书写，笔迹随内容保留、可擦除、按文档持久化。

> **版本**：0.13.1
> **适用设备**：带 Wacom/EMR 数字笔的墨水屏设备（Kindle Scribe / Scribe 3 / Colorsoft）
> **KOReader**：不限版本。新版走官方 stylus API，旧版自动回退到直读数字笔节点
> **仓库**：<https://github.com/sharefoo/pencil-handwriting.koplugin>

---

## 简介

针对 Kindle Scribe 系列的数字笔做了深度适配。输入层**优先复用 KOReader 官方的 stylus 回调**：它已经解析好笔的槽位与工具类型（笔 / 橡皮 / 高亮），并且可以**独占**笔事件，使笔画不会被误判成翻页手势。在较旧、不含该 API 的 KOReader 构建上，自动回退为直接读取数字笔的 evdev 节点（按 `BTN_TOOL_PEN` 能力自动定位节点），因此**不依赖 nightly 版本**也能工作。

**「这一笔是谁写的」不再靠猜。** KOReader 把数字笔和触摸屏的接触点合进同一张表，合并之后来源信息就丢了——手指事件会带着笔的槽位号进来，看起来和笔一模一样。插件改为**只读旁听数字笔节点**（不 `EVIOCGRAB`，KOReader 完全不受影响），在笔回调里顺带读掉这一帧，直接拿到数字笔自己上报的笔尖状态：工具类型、是否接触玻璃、坐标。于是「笔」与「手」有了确定答案，而不是用「离上一个采样点多远」这类阈值去猜：判定为笔才落墨，判定为手就不落墨、也不接管，手指翻页照常。

书写采用**只加墨、不铺白**的方式：每段新笔迹直接画进实时 framebuffer，只刷新笔尖覆盖的矩形区域（fast/DU 局部刷新），页面正文不受影响；同时挂接 `ReaderView:paintTo`，KOReader 每次重绘（翻页、开菜单、旋转、擦除）之后都会把当前页笔画补画回去，所以笔记不会因重绘而丢失。

笔画按**文档页面坐标**存储（用 KOReader 自己的坐标变换测量），因此在 PDF 上改变缩放、滚动或旋转屏幕，笔迹都会跟着内容走，不会错位到别的内容上。

## 主要特性

- **手写笔迹录入**，笔宽 1–24 px、五档灰度可调
- **只有数字笔能书写**：插件旁听数字笔节点（只读、不独占），按数字笔自己上报的「笔尖在不在玻璃上、在哪」判断每个采样是谁发的，手指、手掌、手腕碰到屏幕不留任何笔迹，也不会画出「连接线」，见安装文档 6.6。**旁听节点必须先「证明自己读的就是这支笔」才有资格否决采样**：工具位、笔尖状态、位置三件事各自被笔本身验证过一次之前，插件一律不动墨、把判断交回旧的轨迹判定——所以一个读错节点/读错单位的旁听节点最坏也只是「什么都没做」，而不是「什么都写不出来」
- **手写笔不翻页，手指照常翻页**：判定为笔的采样会被插件接管（KOReader 不会再把笔画当成滑动手势）；判定为手/手指的采样原样放行，翻页、点菜单都正常
- **橡皮擦**（Premium Pen 笔尾或独立橡皮工具），划过即整笔删除
- **按文档持久化**：笔画保存在文档 sidecar 目录，重新打开自动恢复
- **缩放 / 滚动 / 旋转自适应**：分页文档（PDF 等）笔迹锚定在内容上
- **笔记常驻显示**，与「是否开启绘制」解耦：关掉绘制也能看到已写的笔记
- **笔尖接触屏幕时屏蔽触摸**（默认）：这一瞬间的触摸只可能是手，单击 / 长按 / 双击 / 滑动一律不放行，手掌压上去不会翻页也不会误开界面；笔尖一离开手指立刻恢复
- **可选「书写全程屏蔽触摸」**：连笔悬停的时候也屏蔽，适合手一直搭在屏幕上的姿势；代价是这段时间手指也翻不了页，详见安装文档 6.3
- **可选「独占笔输入」**，供直读 evdev 路径下抑制笔触发的翻页
- **输入源可运行时切换**（自动 / KOReader stylus API / evdev 直读）
- **内置诊断面板**：输入源、节点列表、坐标空间、各类计数器与最近错误，绝大多数问题看这里就能定位
- **导出成带笔迹的 PDF**：菜单一键导出笔迹 JSON（自带文档指纹），配合 `pencil-export-server` 网页服务，上传两个文件即得成品 PDF
- **菜单跟随 KOReader 界面语言**：中文界面显示中文（插件名 `Pencil handwriting` 保持不变）

## 安装（速览）

1. 从 GitHub **Download ZIP** 解压后，文件夹名会是 `pencil-handwriting.koplugin-main`——**先把结尾的 `-main` 删掉**，改名为 `pencil-handwriting.koplugin`。KOReader 只认以 `.koplugin` 结尾的目录名，名字不对时插件**既不出现也不报错**，是最难查的一种失败（`git clone` 得到的就是正确名字，不用改）；
2. 把这个文件夹**整个**复制到 Kindle 的 `koreader/plugins/` 下（文件夹内应直接看到 `_meta.lua` 与 `main.lua`，不要再套一层同名目录）；
3. **完全退出** KOReader（不是退回主界面），再重新启动——插件只在启动时扫描一次；
4. 打开任意文档 → 顶部菜单 **第二栏（排版 / Typeset）** → 最下方 **Pencil handwriting** → 勾选 **Enable drawing（启用手写）**。

完整步骤、目录层级陷阱与验证方法见 **[安装操作文档.md](安装操作文档.md)**。

## 使用

### 菜单一览

进入 **主菜单 → 排版 → Pencil handwriting**：

| 菜单项 | 作用 |
|---|---|
| **Enable drawing**（启用手写） | 绘制总开关。按文档记忆，重开同一本书自动恢复 |
| **Width**（笔宽） | 预设 1 / 2 / 3 / 5 / 8 / 12 / 16 / 24（默认 3），或自定义 1–24 |
| **Color**（颜色） | Black / Gray 25% / Gray 50% / Gray 75% / White（默认 Black） |
| **Input source**（输入源） | 自动 / KOReader stylus API / evdev（直读），一般保持「自动」 |
| **Block touch for the whole writing session**（书写全程屏蔽触摸） | 默认关。默认行为已经覆盖笔尖接触屏幕的那段时间；开启后连笔悬停/放在一边时也屏蔽，抬笔约 0.7 秒后手指恢复（详见安装文档 6.3） |
| **Tell the pen from a hand (digitizer check)**（区分手写笔与手掌（校验数字笔节点）） | 临时开关「旁听数字笔节点」做对照：关掉它，插件退回纯轨迹判定。用来判断「写不出字」到底是旁听读错了还是别的原因 |
| **Exclusive pen capture**（独占笔输入） | 默认关，仅 evdev 路径生效，开启有二次确认 |
| **Redraw strokes**（重绘笔迹） | 按已存数据强制重画，界面显示异常时用 |
| **Clear strokes on this page**（清除本页笔迹） | 清除本页，弹窗显示数量 |
| **Clear all strokes in document**（清除本文档所有笔迹） | 清除全文档，弹窗显示总数 |
| **Export stroke data (JSON)**（导出笔迹数据） | 写出一份可直接上传的笔迹 JSON（自带文档名/页数/大小指纹） |
| **Get a PDF with my notes**（怎么得到带笔迹的 PDF） | 就地告诉你该拿哪两个文件、去哪合成 |
| **Full refresh on page turn (test)**（翻页整屏刷新） | 测试用：每次翻页都整屏刷新 |
| **Input diagnostics**（输入诊断） | 诊断面板，排错必看 |

> 菜单文字跟随 KOReader 的界面语言；上表同时给出中文与英文原文，便于对照。

### 书写与擦除

| 操作 | 方式 |
|---|---|
| 写字 | 开启绘制后直接用笔在页面上写 |
| 擦除 | 用笔尾橡皮，或切换为橡皮工具后划过笔画 |
| 翻页 | 用**指尖**滑动。笔尖没压在屏幕上时手指一切照常；只有笔尖正接触屏幕的那一小段时间触摸会被屏蔽，把笔抬起来即可 |
| 点菜单 | 用**指尖**——判定为笔的事件被插件接管，笔点不动菜单 |

> **橡皮擦是「划过即整笔删除」**，不是局部裁剪。因为插件只能加墨、不能涂白（涂白会盖住正文）。

> **「笔尖接触屏幕时屏蔽触摸」为什么不能更宽？** 电容层分辨不出「手指」和「手掌」。不屏蔽的话，手掌在书写时蹭到屏幕就会翻页、误开书签列表；屏蔽整个书写过程的话，手指又没法翻页了。折中点是只屏蔽「笔尖在玻璃上」那一瞬间——那时几乎不可能有人故意用另一只手翻页。想连悬停时也屏蔽，就开 **书写全程屏蔽触摸**。

### 绑定手势

插件向 KOReader 的 Dispatcher 注册了一个动作 **Pencil handwriting: toggle**，可在 **主菜单 → 工具 → 手势管理** 中绑到手势上（例如双指长按切换绘制），不必每次进菜单。

## 数据与备份

笔画数据保存在文档的 sidecar 目录中，文件名固定为：

```
<书名>.sdr/pencil_handwriting.lua
<书名>.sdr/pencil_handwriting.json    # 菜单「导出笔迹数据（JSON）」产出
```

- **备份笔记** = 复制这个文件；换设备或重装后放回同一个 `.sdr` 目录即可恢复。
- 文件由插件自动读写，**不要在设备运行时手工编辑**。
- 删除 `.sdr` 目录会同时清掉笔记、阅读进度、书签等所有附属数据，请谨慎。
- 两个文件都带**文档指纹**（书名、页数、字节大小），导出工具据此确认"这笔迹是不是这本书的"。

### 导出笔迹

笔迹不是图片，别的软件读不了。按目的挑最省事的一条：

**① 只要单页 → 用 KOReader 自带截图。** 两指沿屏幕对角线滑动一次即可，
截图存到 `koreader/screenshots/`（文件名带书名与页号，目录可改）。
笔迹就在屏幕缓冲里，**会被一起截进去**。

**② 要整本带笔迹的 PDF → 把 PDF 拖到 `tools/export.bat` 上。** 不用敲命令：

```
拖 PDF → 自动找到 <书名>.sdr 里的数据 → 结果写到 PDF 旁的 pencil-export\<书名>\
```

首次运行会自动安装 PyMuPDF；**原 PDF 不会被改动**。产出：

| 文件 | 用途 |
|---|---|
| `<书名>_annotated.pdf` | 原页面 + 笔迹，可直接分享、打印 |
| `<书名>_ink.pdf` | 只有笔迹的透明层，供其他工具叠加 |
| `pages/page-0001.png` | 每页渲染图（`--mode png`） |

**③ 想脚本化 / 批处理**，直接调 `tools/export_annotations.py`：

```bash
python tools/export_annotations.py --pdf "D:/books/某书.pdf"    # 最简
python tools/export_annotations.py --pdf a.pdf --mode png       # 每页 PNG
python tools/export_annotations.py --pdf a.pdf --mode all --open
```

笔迹坐标本就是 PDF 的页面坐标（1:1 的点），所以位置与设备上一致。
仅支持分页文档（PDF / DjVu 等）；EPUB 等重排文档的笔迹锚在屏幕坐标上，无法映射，
脚本会明确报告跳过了多少笔。完整说明见 [安装操作文档.md](安装操作文档.md) 第九节。

**④ 不想在自己的电脑上装东西 → 用 `pencil-export-server` 网页服务。** 服务器上跑一次
`python app.py`（只依赖 PyMuPDF），之后在任何设备（手机、平板、网吧电脑）打开网页，
把 **PDF** 和 **笔迹文件**（`pencil_handwriting.lua` / 菜单导出的 `.json` / 打包的 `.zip`）
拖进去，当场得到带笔迹的 PDF、首页预览和一份对账报告。设备端配合：

```
主菜单 → 排版 → Pencil handwriting → 导出笔迹数据（JSON）
```

会写出 `<书名>.sdr/pencil_handwriting.json` —— 一个单文件、好上传、自带文档指纹的笔迹文件。
详见 [pencil-export-server/README.md](../pencil-export-server/README.md)。

## 已知限制

- 不支持逐笔选中、改色、移动
- 橡皮擦为整笔删除，不能局部裁剪
- 无压感调宽（不读取压力值调制笔画粗细）
- **重排文档（EPUB / FB2）**：KOReader 不提供页面坐标系，笔画只能锚在屏幕坐标上，改动字号或版式后位置可能漂移。批注建议用 PDF
- 早期版本（存储格式 v1，屏幕坐标）写下的笔迹在加载时会被跳过，需要重画
- 绘制开启时笔无法操作菜单，需用指尖
- **一个「接触」的身份一旦判定就保持到它抬起为止**：这是 KOReader 手势检测的机制决定的（它按槽位追踪接触，只认抬笔结束）。所以如果手腕在**笔画进行中**才落到屏幕上，那几帧会被算进这笔（而不是被丢掉）；反过来，手掌先落下、笔随后压到同一个接触上时，插件会把该接触从手势检测里撤下来再接管（这不会漏掉抬笔，所以不会卡住触控）
- **打开文档后一次都没写过字、就先把手掌压到屏幕上**：此时「笔尖没落下」这条判据还没来得及被验证，那一笔会按旧的轨迹判定处理（可能起一笔，抬手后删掉即可）。**只要写过一笔，这个窗口就永久关闭**——这是「宁可偶尔多画一笔，也绝不整场写不出字」的刻意选择
- 墨迹极密的页面，翻页会变慢

## 常见问题

| 现象 | 先看这里 |
|---|---|
| **菜单里找不到 Pencil handwriting** | 头号原因是**解压后的文件夹名还带着 `-main`**——KOReader 只认以 `.koplugin` 结尾的名字，删掉 `-main` 后重新复制（见「安装（速览）」）。其次：必须**打开文档后**在阅读界面看；插件只在启动时扫描，装完要**完全重启** KOReader |
| 插件加载失败并弹窗 | `pencilhw/` 子目录缺失或损坏，或外面又多套了一层同名目录，重新完整复制整个文件夹 |
| 开启了绘制但写不出笔画 | 把 **Input source** 切到「自动」，再打开 `Input diagnostics` 看节点与坐标 |
| 写不出笔画，怀疑旁听读错了 | 看诊断面板的 `pen oracle trust:` 一行：**`min dist` 应该是个位数到几十像素**。若是几百甚至上千，说明旁听节点与 KOReader 不在同一个坐标空间，它不会否决任何采样（不会吞墨），但也没在起作用；此时在菜单里把 **Tell the pen from a hand (digitizer check)** 关掉做对照 |
| 写字被识别成翻页 | 输入源保持「自动」；看诊断面板的 `pen oracle` 一行是否为 `listening`；仍复现则开启 **Exclusive pen capture** |
| 手掌蹭到屏幕会翻页 | 只在笔尖离开屏幕之后发生是正常的（那一刻触摸就是「手指」）。想连这种情况也盖住，开启 **书写全程屏蔽触摸** |
| 手指翻不了页 | 检查是否开着 **书写全程屏蔽触摸**（关掉即可），以及笔尖是不是正压在屏幕上；诊断面板 `touch block: level=` 会告诉你当前屏蔽的是哪一档 |
| **笔碰过屏幕之后，手指点/滑都没反应（像卡死）** | 先看诊断面板的 `slot answers:` 一行：抬笔之后它应该是 `none`。若某个槽位一直挂着 `=skin`，说明那个接触的「抬笔」没被看到，是本类问题；先把 **Tell the pen from a hand (digitizer check)** 关掉（退回纯轨迹判定）作为应急，再把这行反馈 |
| 写不出笔画、但以前能写 | 看诊断面板的 `pen oracle` 一行：若显示 `gave up`，说明旁听没有读到笔（节点或坐标不匹配），插件已退回旧的阈值判定；把这一行连同 `pen oracle trust:` 一起截图反馈 |
| 翻页时手指偶尔被吃掉一次 | 看 `slot answers:` 与 `frames handed back to a finger=`：后者随手指操作增长说明放行正常；前者若在抬笔后没清空，同上一条 |
| 笔迹翻页后消失 | 看诊断面板的 `Repaint hook` 是否为 `MISSING` |
| 笔迹出现在相邻页 | 看诊断面板的 `stroke space` 与 `Last stroke`（正常应为 `space=page`） |
| 橡皮擦没反应 | 看诊断面板的 `erase unmapped` 计数与 `Last slot` 的 `tool=` 值 |
| 想把笔迹导出成 PDF 或图片 | 单页用 KOReader 截图（两指对角滑动）；整本用 `tools/export.bat`（拖 PDF 上去）；不想装东西就用 `pencil-export-server` 网页服务。见上文「导出笔迹」 |
| 合成结果和原书对不上 | 一般是拿错了书/拿错了笔迹文件；网页报告会比对文档指纹并给出告警 |
| 菜单仍是英文 | 看诊断面板的 `language:` 一行；界面语言不是中文时菜单就保持英文 |

详细的判读方法与完整排错表见 **[安装操作文档.md](安装操作文档.md) 第八节**。

```
    ├── viewmap.lua      屏幕 ⇄ 文档页面坐标（向 KOReader 实测，逐页映射）
    ├── evdev.lua        直读数字笔节点的回退路径（设备发现、事件解析）
    ├── canvas.lua       无状态光栅器：把笔画画进指定的 Blitbuffer
    ├── store.lua        按页序列化笔画到 sidecar（并导出 JSON）
    └── i18n.lua         菜单文本的语言词典
```

> 复制到设备上时，**必需的只有 `_meta.lua`、`main.lua` 与 `pencilhw/` 整个目录**。
> 其余内容（两份文档、`assets/` 收款码、`tools/` 导出脚本）都可以不带，不影响书写与擦除。

配套的合成服务在上一级的 **`pencil-export-server/`**（零框架 Web 服务 + PyMuPDF），
把 PDF 与笔迹文件合成成带笔迹的 PDF / 每页 PNG。

## 兼容性

- **输入路径**：KOReader nightly 2026.07.2-60 及以后提供 stylus 回调 API，插件优先使用；更早的构建自动走 evdev 直读。
- **文档类型**：分页文档（PDF / DjVu / CBZ）为最佳场景；重排文档（EPUB / FB2）可用，但位置会在版式变化后漂移。
- **其他品牌**：设备发现按「是否上报 `BTN_TOOL_PEN` / `BTN_TOOL_RUBBER`」的能力判断，理论上有 Wacom/EMR 数字笔的机型都可用；目前只在 Kindle Scribe 系列上实测过。
